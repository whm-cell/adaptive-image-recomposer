# Model-led whole-canvas workflow

This workflow describes an observable functional decomposition. It is not a claim about a model's hidden chain of thought or proprietary implementation.

## The work performed

1. **Perceive the source:** recognize asset type, headline, repeated items, values, visual hierarchy, and source layout habits.
2. **Freeze a closed content budget:** verify the visible-text whitelist, object cardinalities, item count, unknown-value policy, and repeated group schemas.
3. **Build a content graph:** bind each object to its name, values, qualifiers, and provenance. Separate factual content from decorative motifs.
4. **Classify asset readiness:** distinguish transparent originals, clean flats, flattened crops, and unavailable assets; choose semantic resynthesis or an auditable preparation path.
5. **Suppress the old grammar:** name the source topology, reading path, containers, and motifs that must not return.
6. **Diverge structurally through capacity gates:** reject kernels that cannot carry the measured content load before comparing compatible families, topologies, and reading paths.
7. **Prepare decision cards:** add wireframes, changed axes, product/text embedding grammar, asset gate, measured capacity margin, and risk.
8. **Pause for a human:** accept one explicit choice and bind it to the route fingerprint. Do not infer agreement from the first or highest-scoring lane.
9. **Solve semantic nodes jointly:** coordinate each object, its copy, silhouette, type anchor, material interaction, connector, negative space, and whole-canvas hierarchy.
10. **Pause at the provider boundary:** bind one explicit human authorization to the compiled prompt and plan. This records permission for one request; it does not invoke or control the provider.
11. **Render or compose by contract:** semantically resynthesize low-risk objects, or place prepared/locked assets into the same final node geometry.
12. **Preserve the observable outcome:** record the provider result. Show every returned artifact immediately; report a no-artifact provider failure and its billing uncertainty.
13. **Audit bidirectionally:** compare required text to observed text, observed text to the whitelist, declared objects to observed objects, and stable IDs to declared groups. QA labels but never hides a returned artifact.
14. **Edit the latest result only after a new human decision:** fix one named defect while freezing the successful lane and all invariants. Never retry automatically.

The main leverage comes from suppressing the old grammar, exploring structurally distinct lanes, and compiling only the selected lane. Useful kernels can be path-led, editorial, modular, radial, spatial, typographic, tactile, or diagrammatic. No one family is the general answer.

## Initial generation contract

Give the model:

- the edit target or factual reference;
- the output use and aspect;
- one selected topology kernel and reading path;
- one paired visual system;
- one product-embedding and one text-embedding grammar;
- content-group bindings;
- exact visible copy;
- the complete visible-text whitelist, object cardinalities, item count, and group schemas;
- semantic-object versus pixel-lock policy;
- prepared-asset readiness and edge-band policy;
- source layout features to suppress;
- no-invention constraints.

Ask for a **whole-canvas joint reconstruction**, not an empty background. Every product-and-copy group is one semantic node, even when exact copy or protected pixels are produced by deterministic layers. Do not paste the direction library or six candidate lanes into the final prompt. If multiple concepts should be rendered, obtain separate human choices and compile them independently.

## Iteration contract

Use the latest generated result as the edit target and retain the original as factual reference. The repair prompt contains:

1. one defect to fix;
2. what is already successful and must remain unchanged;
3. the selected direction family, kernel, reading path, and visual system;
4. the affected exact strings or group binding;
5. no-extra-text and no-new-object constraints.

Examples of single defects include one wrong number, one migrated item value, insufficient title dominance, or a path-led layout collapsing into ordinary columns.

The repair prompt is not permission to spend another provider call. Obtain a fresh one-use `targeted_repair` authorization before invocation. A no-artifact provider failure similarly requires a separately authorized `provider_retry`. Across both follow-up kinds, permit at most two human-authorized calls; the ceiling is not an automatic retry budget.

## What the model-led result does not prove

- It does not prove pixel equality of products, people, or labels.
- Legible-looking dense copy is not proof of exact copy.
- Correct strings somewhere on the canvas do not prove correct item associations.
- Human visual approval does not override a failed text, count, or association diff.
- A plausible product rendering is not an authoritative packaging source.
- A clean-looking edge is not proof that a rectangular source background or color spill was removed correctly.

Use hybrid, locked, or deterministic production when those proofs matter.
